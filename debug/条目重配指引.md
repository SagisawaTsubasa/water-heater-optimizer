# v0.4.0 条目重配指引（v0.3.0 升级用户）

v0.4.0 砍掉触发器体系、水温数据源改为 24h 均值实体。升级后旧条目**不需要删除重建**，按下文三步重配即可。

## 旧条目升级后会发生什么（自动，无需干预）

- 旧条目配置里残留的 `trigger_*` 键（触发类型/实体/时间等六项）：v0.4.0 代码合并配置后**不读这些键**，dict 合并语义下无害，不报错、不影响运行——无需清理，也无需手动改 storage。
- 旧「Reference Tap Temperature」实体：v0.4.0 已砍除该实体，集成启动时会自动清掉注册表残留（日志可见「已清理旧版 Reference Tap 实体注册表条目」），不会留下永久 unavailable 的幽灵实体。
- `take_snapshot` 服务已随触发器体系移除：如有自动化仍调用它，会报「服务不存在」——v2 语义下无需快照，均值变化自动驱动重算，删掉相关自动化动作即可。

## 重配三步

### 第 1 步：建 filter 辅助实体

按《filter辅助建法.md》建好 24h 均值实体（UI 或 YAML 均可）。

### 第 2 步：inlet 传感器改指均值实体

1. 设置 → 设备与服务 → 找到 Water Heater Optimizer 条目 → **配置**（Configure）。
2. 「**24h 平均进水温度传感器**」字段：从旧的进水温度传感器改为第 1 步新建的 filter 均值实体（该字段只列温度类传感器，filter 均值实体会继承源传感器的温度类属性，可选到）。
3. 其余字段（热水器/目标温度/比例/上下限）不动，提交。
4. 提交后条目**自动重载**（实体指向属结构性变化），均值监听随即转向新实体；重载完成时集成会立即读一次当前均值并算出推荐值。

### 第 3 步：开总闸

打开 `switch.<条目名>_auto_adjust`：
- 总闸默认 off，状态跨重启自动恢复。
- **开启即比对**：若当前已有推荐值且与热水器设定不同（整数比对），立即下发一次；相同则不动。
- 关闸期间推荐值照常刷新，只是不下发。

## 验证清单

- [ ] `sensor.<条目名>_recommended_temperature` 重载后数秒内有值（不 unknown）。
- [ ] 该实体属性 `inlet_temp_sensor` 指向 filter 均值实体；下发成功后 `applied_temp` 出现本次值。
- [ ] 日志（记录器 `custom_components.water_heater_optimizer`）可见「24h 均值变化: avg=X°C → recommended=Y°C」。
- [ ] 总闸 off 时改均值：推荐值刷新、热水器不动；总闸 on 且推荐值与当前设定不同：热水器设定被改写。

## 排障速查（跳过路径全部 INFO 落因，不再静默）

| 情形 | 行为 | 日志
|---|---|---|
| 均值实体 unavailable/unknown | 忽略本次变化，不重算；推荐值显示上次恢复值 | INFO「avg 实体 … 状态为 …，忽略本次变化」
| 均值整数值没变 | 不重算、不下发 | 无（属正常静默）
| 均值整数变化 | 重算+刷实体；总闸开才比对下发 | INFO「24h 均值变化 …」
| 推荐值 = 热水器当前设定（整数比对口径） | 不下发（相同不动） | DEBUG
| 热水器状态缺席 / 设定温度不可读 | 跳过本次下发，等下次均值变化重试 | INFO 落因
| 下发服务调用失败 | 不更新 applied_temp | ERROR「下发设定温度 … 失败」
| 总闸开着但尚无有效均值 | 暂不下发 | INFO「自动调节已开启，但当前无推荐值」

> v0.3.0 曾因触发过滤静默不匹配停摆 43 天无任何日志。v0.4.0 所有跳过路径至少 INFO 落因——看到推荐值不动时先查上述日志行。
